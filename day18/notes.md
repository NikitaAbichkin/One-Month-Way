**Circuit Breaker** - часть кода которая по статистике ошибок решает  выполнять запрос или нет. (Живет у вызывающего)

Closed - состояние когда мы отправляем вызовы
Open - состояние когда мы не отправляем вызовы
Half_Open - состояние когда мы отправляем запросы для сбора статистики ( чтобы выбрать состояние)

переход с closed -> open записывается таймер сколько секунд будет  Open, за этот промежуток все запросы отклоняются, потом когда наступает Half_Open он ждет отправленных `n` пока они не придут.


**Count-based** sliding window (окно по количеству) - массив куда каждый вызов определяется как (успешный/неуспешный) и каждая новая запись вытесняет последнюю, тема самым статистика всегда новая.

**Timebased** - Корзина по секундам хранит в себе ровно одно значение(секунда). Когда приходит новая секунда которая должна  занять  корзину, мы выходим и вычитаем данные из "общих"


Один запрос может быть и `failed` and `slow`

Список Exceptiont которые считаются ошибкой и список которые ни(failed/seccess)
ignore - не записываем
record - считаем за ошибку

#### Retry
Повторяемые запросы ( если DataBaseException ) то можно повторить запрос, если же SQException то нет смысла повторять

**exponential backOff**  - когда пауза увеличивается  постепенно ( можно указать максимальную паузу,  множитель)

**Jitter** - случайный разброс паузы ( делается для того чтобы в сервис не ломились все потоки  одновременно

**ReadTimeout** - максимальное время сколько поток будет ждать порцию байтов  по http запросу после обращения) Отвечающий может давать ответ порциями с интервалом. И в итоге  ответ будет идти долго
**TimeLimiter** - максимально время на весь запрос. Либо за 2с пришел ответ полностью либо нет. Принимающий поток делает запись и ее выполняет пулПотоков-исполнителей, если его  поток-исполнитель  не ответил за `n` секунд то он отвечаем Exception

**Bulkhead** - ограничение на количество потоков для вызова( вызов к inventory  -> 30 потоков из 200).

**Fallback** - метод который вызывают вместо проброса исключения.(получили ошибку, и возвращаем тот же тип что  должен быть возвращен)


Порядок 
1) Retry - повторяемый Exception  или нет, ( сколько ждать перед повтором)
2) CircutBreaker - обрезаем запрос если OPEN(много запросов приходят с ошибкой)
3) RateLimitter - время на весь запрос (через передачу выполнения в пул потоков)
4) Bulkhead - максимальное количество потоков на вызов эндпоинта

**Стандартное расположение**
Retry( CircuitBreaker( TimeLimiter( Bulkhead( твой метод ))))
